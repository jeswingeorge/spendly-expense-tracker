## Skills Definition

Skills are reusable, file-based resources that provide Claude with domain-specific expertise such as workflows, context, and best practices that transform general-purpose agents into specialists.

Unlike prompts (instructions for one-off tasks), Skills load on-demand and eliminate the need to repeatedly provide the same guidance across multiple conversations.

So if its a skill for creating PPT then it will have all the related things for the PPT such as layout, font-size, color schema, slide structures, when tables needs to be added, when tables/charts needs to be added, etc.

If additional resources are needed by the skill then you can create a dedicated folder for that too. Like we can have `Scripts`, `template` folder.  
* `Scripts` folder - Example for a data analyst some python scripts
* `template` folder - Example for PPT a template with file and folder structure


### SKILLS Folder Structure

A Claude skill folder requires a root directory named in kebab-case containing a case-sensitive `SKILL.md` file.

```
your-skill-name/
├── SKILL.md              # Required: Main instructions with YAML frontmatter
├── scripts/              # Optional: Executable code (Python, bash, etc.)
├── references/           # Optional: Additional documentation or API guides
├── templates/            # Optional: Reusable file or code templates
└── assets/               # Optional: Static files, images, or configuration data
```
 #### Critical Rules for Skill Structure 

* **Folder Naming**: Use kebab-case (e.g., ); avoid spaces, capitals, or underscores. 
* **File Naming**: The main instruction file must be named exactly  `SKILL.MD`(case-sensitive). Do not include a `README.MD`  inside the skill folder.
* **YAML Frontmatter**: Every `SKILL.MD` must start with a metadata block defining the `name` (matching the folder) and a detailed `description` telling Claude precisely when to activate the skill. 

## SKILL.md file

A `skill.md` file is the mandatory core component of any *Claude Code* skill. It acts as the configuration and instructional guide for the AI agent, structured into two main parts :

**1. YAML Front Matter (Metadata):**
Located at the very top of the file, this defines how *Claude* identifies and triggers the skill .
* **Name:** A unique identifier for the skill.
* **Description:** A crucial field that tells *Claude* when it should automatically invoke the skill based on the user's request .

**2. Markdown Body (Instructions):**
Following the YAML section, this contains the detailed guidance and logic for the specialized task .
* **Instructions:** Contains best practices, step-by-step workflows, and specific patterns for the task .
* **Validation:** Defines how to check for errors and ensure high-quality output .
* **Resource Links:** If the skill requires supporting files (like Python scripts or design templates), their file paths are linked here, allowing the agent to fetch them when needed.

### Example of a SKILL

#### Concept / Why It Matters

A `SKILL.md` file defines a modular, repeatable workflow that Claude Code executes when invoked via a slash command (or auto-triggered by prompt intent). For beginner data scientists, jumping straight into exploratory data analysis (EDA) often leads to skipped steps—like checking missing values, identifying skewed distributions, or verifying data types—which leads to bad models.

This skill standardizes the initial data audit process into a single, automated, production-grade report using `pandas`, `seaborn`, and `scipy`.

---

#### Real-World Scenario

You just received a raw dataset (`data/customer_churn.csv` or `housing_prices.parquet`) and need a comprehensive exploratory report before doing any feature engineering or modeling. Instead of re-writing boilerplate Pandas code, you invoke `/eda-audit` (or ask Claude Code to "run a data audit"), and Claude automatically inspects the schema, detects missing data patterns, checks for statistical outliers, generates visualization scripts, and outputs an actionable summary report.

---

#### Exact Configuration & Code

Create the skill file in your project's `.claude/skills/` directory.

##### File Path: `.claude/skills/eda-audit.md`

```markdown
---
name: eda-audit
description: Runs a standardized Exploratory Data Analysis (EDA) audit on a given dataset file (CSV/Parquet/Excel) and outputs a comprehensive statistical report with diagnostic plot scripts.
triggers:
  - "/eda-audit"
  - "run data audit"
  - "perform eda on"
inputs:
  - name: dataset_path
    type: string
    description: Path to the dataset file (e.g., data/raw_data.csv)
    required: true
  - name: target_column
    type: string
    description: (Optional) The target or outcome variable name for supervised analysis
    required: false
---

#### Skill: Exploratory Data Analysis (EDA) Audit

##### Prerequisites
- Python environment with standard data science packages installed:
  `pandas`, `numpy`, `matplotlib`, `seaborn`, `scipy`
- PowerShell 7 runtime for Windows file verification.

##### Step-by-Step Execution Plan

1. **Verify Dataset Existence & Format**
   - Check if `<dataset_path>` exists using PowerShell:
     ```powershell
     Test-Path "<dataset_path>"
     ```
   - If the file is missing, halt execution and inform the user.

2. **Generate Baseline Inspection Script**
   - Execute a transient Python script to extract key statistical properties:
     - Dataset dimensions (rows × columns) and memory consumption.
     - Column data types (`dtypes`) and count of unexpected non-numeric types.
     - Count and percentage of missing values per column.
     - Cardinality of categorical variables (unique values).
     - Skewness and kurtosis for numeric columns.
     - Pearson/Spearman correlation matrix (if `<target_column>` is provided).

3. **Identify Data Quality Flags**
   - Highlight **high missingness** (> 20% missing values).
   - Highlight **high cardinality** (categorical features with > 50 unique values).
   - Highlight **severe class imbalance** (if `<target_column>` is categorical and any class is < 10% of total).
   - Highlight **multicollinearity** (pairs of features with correlation $|r| > 0.85$).

4. **Generate Visualization Code**
   - Create a clean, executable script saved to `scripts/generate_eda_plots.py`:
     - Distribution plots (histograms + KDE) for skewed numeric features.
     - Box plots for outlier detection.
     - Heatmap of missing data patterns using `seaborn.heatmap`.
     - Correlation matrix heatmap.

5. **Output Final Audit Summary**
   - Print a Markdown-formatted summary report to the console covering:
     - Dataset Health Rating (Good / Action Required / High Risk).
     - Recommended Data Preprocessing Steps (imputation strategies, encoding methods, scaling choices).

##### Guardrails & Execution Rules
- **Non-Destructive Only:** Never overwrite or alter the source dataset file.
- **Path Escaping:** Always wrap file paths in double quotes to handle Windows paths with spaces (e.g., `"C:\Users\Name\My Data\file.csv"`).
- **Resource Management:** If the dataset exceeds 500,000 rows, use a randomized 20% sample (`df.sample(frac=0.2, random_state=42)`) for visualization generation to optimize processing speed.

```

## Progressive Disclosure
How does skill gets loaded into context-window?  

**Core Idea**: Dont present information until the moment its needed.  

Progressive disclosure is a technique used to save your **context window** by only loading necessary information at the exact moment it is required. This process happens in three distinct levels:

* **Level 1 (Metadata) - (ALWAYS VISIBLE):** At the start of every session, the **YAML front matter** (the skill's name and description) is loaded into the context window . This informs *Claude* which skills are available and when they should be triggered without wasting space on full instructions.
* **Level 2 (Instruction Body) - (LOADED ON DEMAND):** When you issue a prompt that matches a specific skill's description, *Claude* then loads the full **Markdown body** of the `skill.md` file into memory .
* **Level 3 (Resources) - (LOADED IF NEEDED):** Finally, if the skill's instructions require external dependencies—such as *Python scripts* or *template files*—those specific resources are fetched only when the model needs to execute them .

By following this layered approach, your AI agent remains highly efficient, avoiding the clutter of large system prompts while ensuring specialized knowledge is ready exactly when you need it .

## Ways to create skills

There are three primary ways to create *Claude Code* skills :

1. **Manual Creation:** You can manually create a folder, define a `skill.md` file, and write the detailed instructions yourself. While technically straightforward, this is generally not recommended for beginners who may not be familiar with the required format or structure.
2. **Using Claude (Recommended):** You can use the built-in *Skill Creator* within the *Claude* chat interface. By selecting the skill creator, you can describe your needs in your own words, and *Claude* will help draft, refine, and finalize the skill for you . This is the suggested approach for beginners .
3. **Community Sources:** You can install pre-existing skills created by others from community marketplaces. While convenient, it is important to exercise caution and review the content of these skills to avoid security risks, such as accidental exposure of API keys. *Anthropic*'s official repository is a safer alternative if you choose this route.
   1. [Skillsmp](https://skillsmp.com/)
   2. [Anthropic Skills Public Repo](https://github.com/anthropics/skills)

## Steps to creata skill

Creating a skill in *Claude Code* involves a structured workflow to ensure the AI agent can effectively handle specialized, repetitive tasks . Here are the essential steps:

1. **Identify the Need**: Focus on creating skills only for tasks that are **highly specialized** and need to be performed **repeatedly** .
2. **Setup the Directory**: Create a dedicated folder for the skill within your project's `.claude/skills/` directory.
3. **Create `skill.md`**: Inside that folder, create a `skill.md` file. This must include:
   * **YAML Front Matter**: Define the skill **name** and a clear **description** .
   * **Markdown Body**: Provide detailed instructions, best practices, and validation steps (13:30, 22:31).
4. **Add Resources**: If the skill requires external files (like scripts or templates), place them in subfolders within the skill directory and link to them in your markdown file.
5. **Test and Iterate**: After creation, test the skill against real prompts to identify any issues . Iterate on the instructions until you achieve reliable, high-quality output .


## Issue of using Prompt as an alternative to Skills

Using long, manual prompts for repetitive tasks presents several limitations: 

* **Repetitive Effort:** You must manually re-type or copy detailed instructions every time.
* **Context Window Waste:** Including massive system prompts consumes limited token space even when not needed.
* **Resource Management:** It is difficult to attach external files, scripts, or design assets to a simple prompt.
* **Maintenance Issues:** Prompts are often personal and hard to version, share, or improve across a team.
* **Lack of Composition:** You cannot easily chain multiple specialized tasks together without confusing the AI.
