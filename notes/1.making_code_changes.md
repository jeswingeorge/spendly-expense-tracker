## Prompting in Claude

**Question: In claude dont we need to give persona and context while giving prompt in a project?**

Short answer: **persona — no; context — partly automatic, but you still steer it.**

**Persona is already baked in.** Claude Code ships with a system prompt that makes it a software-engineering agent. Adding "You are an expert senior Python developer" to your prompt adds nothing and sometimes hurts (it can push toward generic textbook style instead of matching your codebase). This is different from the raw API or claude.ai chat, where you'd construct that role yourself.

**Context is gathered on demand, not preloaded.** It doesn't read your whole repo up front. What it gets automatically:
- The working directory + a file listing
- `CLAUDE.md` files (global at `~/.claude/CLAUDE.md`, project root, and directory-scoped ones)
- Git state when relevant
- Memory files, if set up

Everything else it discovers by *searching and reading files while working* — driven by what your prompt points it at. So a vague prompt means it guesses where to look; a prompt that names the file, feature, or symptom means it goes straight there.

**Where each kind of context belongs:**

| Thing | Where it goes |
|---|---|
| Durable conventions, stack, build/test commands, "always do X" | `CLAUDE.md` (write once, applies every session) |
| Your preferences as a user (you already have Ollama/Windows notes there) | global `CLAUDE.md` |
| This-task-only detail: the goal, the constraint, the acceptance criteria, relevant paths | the prompt |

**What a good prompt actually needs** — not persona, but:
1. The concrete outcome you want
2. Constraints ("don't touch the auth module", "keep it dependency-free")
3. Pointers if you know them (`src/components/Landing.tsx`)
4. How you'll judge it's done (tests pass, matches this mock, etc.)

So instead of *"Act as a senior frontend engineer. This is a React expense tracker. Improve the landing page."* → just *"Improve the landing page: tighten the hero copy, make the feature grid responsive on mobile, keep the existing Tailwind tokens."* The second is shorter and gets better results.

One caveat: for a long or multi-part task, front-loading *why* still helps — not persona, but intent ("this is for a portfolio demo, so visual polish matters more than bundle size"). That's the kind of thing it genuinely can't infer from the code.
